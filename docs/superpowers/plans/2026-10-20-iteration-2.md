# radiolisp iteración 2 (favoritas) — Implementation Plan

> **For agentic workers:** executed inline (superpowers:executing-plans) on branch
> `feat/favorites`. The user delegated approval and reviews at the end, so tasks
> list files, tests and checks rather than repeating every line of code; the code
> is in the commits.

**Goal:** Implement `docs/specs/2026-10-20-iteration-2-design.md`: a favourites grid
with persistence, reordering and hand-assigned keys, a bottom player bar, a
Radio Browser palette, M3U export/import, votes, click counting, HLS via a lazily
loaded hls.js module, and Media Session.

**Architecture:** unchanged flow (action → pure `handle` → effects). New pure code
goes to `common/` (`favorites.cljc`) so a future backend can reuse it.

**Tech:** as in the MVP, plus `hls.js@1.7.3` (npm) in a separate shadow-cljs module.

**Every task ends with** `bb test` (read the redirected log), `bb lint`,
`bb fmt:check` and a commit.

## Deviations found while executing (2026-10-20)

The task list above is the plan as written; the repository is the source of truth.

- **Order.** i18n (Task 4) was done together with the views (Task 8), once the
  keys they need were known. Tasks 8 and 9 went into one commit.
- **`common.favorites`** also has `member?`. `deserialize` returns the favourites
  vector (not the whole map), and `assign-key` refuses reserved keys itself.
- **`art/fit`** never returns `:broken`: an image that loaded but reports no size
  (some SVGs) is `:contain`. `:broken` only comes from the `error` event.
- **Import** is one effect, `[:api/import {:server :ids :urls}]`, which resolves the
  uuids with one `byuuid` request and each plain URL with `byurl`, and answers with
  `[:import/resolved {:stations :missing}]`. Coordinating two effects in the pure
  core was not worth it.
- **Menus** are fixed elements placed next to their button by `:dom/place-menu`,
  with a transparent scrim behind them that closes them on any outside click.
  `↓ ↑ j k` move through the items (`:menu/move`).
- **Tiles** are an `<article>` with a full-size play `<button>` (artwork and name)
  and the key and menu buttons as siblings, so nothing interactive is nested.
- **Events.** `main` stops propagation of every DOM event it handles (the innermost
  handler wins: the ♥ inside a palette row does not also play it), turns off the
  browser defaults of `dragover` and `drop`, and sets drag data on `dragstart`
  (Firefox needs it).
- **Removed:** the elapsed-time clock of the MVP player (the spec's data line has
  no room for it), with `:clock/tick`, `:started-at`, `:now` and
  `common/format.cljc`.
- **The palette** has a close button too (phones have no Esc).
- **Media Session:** `audio.cljs` sets `playbackState` from the element's own
  events; `[:media/update …]` only sets the metadata.
- **hls.js** needed `:module-loader true` in the build and `["hls.js" :as Hls]`
  (its UMD build exports the class itself, so `:default` is undefined). Chromium
  now plays HLS natively, so the e2e hides native support (`canPlayType`) to
  exercise hls.js.
- **e2e** counts only GET requests: the `X-Requested-With` header makes the
  browser send CORS preflights too.
- **Design inspector:** 0 FAIL at 1440/768/390, on the empty state and on a seeded
  grid. One WARN, `hero-void`, with few favourites: the grid grows with the list,
  so the space below it is the list's room, not a layout gap.
